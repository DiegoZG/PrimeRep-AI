## Reproduce safely

Connect only the approved guest to the coordinator's verified candidate server. `MODE` and `SCREENSHOT_PREFIX` are required CLI values with no YAML defaults; prefixes must point into an existing absolute private directory.

```sh
xcrun simctl openurl A21DA251-8A4F-45E3-8E6D-763EDD2277D3 'primerepai://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8083'
maestro --udid A21DA251-8A4F-45E3-8E6D-763EDD2277D3 test -e MODE=empty -e SCREENSHOT_PREFIX=/absolute/existing-dir/u26-empty .maestro/custom-split-refinement.yaml
maestro --udid 67BF52B6-AC88-4620-841C-2970B1D5AF0D test -e MODE=compact -e SCREENSHOT_PREFIX=/absolute/existing-dir/u26-compact .maestro/custom-split-refinement.yaml
```

Never run creation against an unexpected nonempty list; stop and request direction rather than deleting existing data. Under the explicit fictional-day test authorization and normal Large text, `open-add` opens the actual modal; `commit-upper` creates the first Upper day and proves its one-day route. Read its actual new ID from `maestro hierarchy --compact`. `add-second` requires `FIRST_ID`, creates the duplicate Upper, and opens the Custom tab; `commit-custom` creates the thirteen-muscle Custom day. Read the new second/custom IDs from the public hierarchy. Creation is not idempotent: do not blindly repeat a stage after any successful Add.

```sh
maestro --udid A21DA251-8A4F-45E3-8E6D-763EDD2277D3 test -e MODE=normal -e FIRST_ID=OWN_FIRST_ID -e SECOND_ID=OWN_SECOND_ID -e CUSTOM_ID=OWN_CUSTOM_ID -e EDIT_ID=OWN_SECOND_ID -e SCREENSHOT_PREFIX=/absolute/existing-dir/u26-light .maestro/custom-split-refinement.yaml
maestro --udid A21DA251-8A4F-45E3-8E6D-763EDD2277D3 test -e MODE=normal -e FIRST_ID=OWN_FIRST_ID -e SECOND_ID=OWN_SECOND_ID -e CUSTOM_ID=OWN_CUSTOM_ID -e EDIT_ID=OWN_CUSTOM_ID -e SCREENSHOT_PREFIX=/absolute/existing-dir/u26-dark .maestro/custom-split-refinement.yaml
```
